# Evaluation protocol (to earn claims before making them)

The skill makes no claim of being better than a plain prompt until this has been run and the results published, including bad ones.

## Setup
- 5 real screens with permission to publish (mix: form, list, dashboard, checkout or booking, onboarding). Record the brief for each.
- Condition A: the same model, a plain prompt ("redesign this screen, keep content and functions").
- Condition B: the same model with this skill.
- Same inputs, same output target, no manual edits.

## Rating
- 3 or more designers, blind to the condition, order randomized.
- Score 1 to 5 on: hierarchy, usability, accessibility, visual craft, distinctiveness, fidelity to content and function.
- Add measured items per output: contrast failures, target-size violations, steps to the main task, count of competing emphasis levels.

## Report
- Publish the scores, the raw outputs and the rater instructions.
- State sample size and the limits (5 screens, few raters, one model version).
- Do not write "better" or "proven"; write what was measured.

## Management-report check
For each run, check that every decision in the report points to a real P-number and that no number is invented.
